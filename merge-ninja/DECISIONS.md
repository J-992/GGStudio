# Decisions

Short log. Newest last.

- **Stack pinned:** Vite 6 + Phaser 3.90 + TypeScript 5.9, ESLint 9 flat config, Vitest 3. Phaser 4 exists but PLAN.md specifies Phaser 3 and its API surface is what the team knows.
- **Phaser-free core.** Everything in `src/data/` and `src/systems/` is pure TypeScript with no Phaser import, so the merge/economy/combat/progression rules are unit-testable in a Node environment. Phaser only appears in `scenes/`, `entities/`, `ui/`, `effects/`. This is the main testability lever.
- **Board is data, view is a mirror.** `MergeSystem` owns a `(Ninja | null)[12]` array. `MergeBoard` renders it and reports intents (drop A on B). No gameplay state lives in display objects.
- **Placeholder art is generated at runtime into a real texture atlas.** `BootScene` draws 12 tier sprites into one canvas texture with named frames (`ninja_t1`…`ninja_t12`, `enemy_e0`…). Swapping in Higgsfield art means dropping a PNG + JSON atlas into `public/assets/` and flipping one flag in `src/data/atlas.ts` — no logic touched (PLAN.md revision 5).
- **Buy tier escalation** per PLAN revision 1: `buyTier = max(1, highestTierEverOwned - 4)`, cost `round(10 * 1.05^purchases) * 2^(buyTier-1)`.
- **Save format** is a single flat JSON blob under one localStorage key, debounced 1s, with a schema `v` field for cheap forward-compat rejection. Corrupt/foreign saves are discarded silently and the run starts fresh — a kid should never see a load error.
- **Audio is procedural WebAudio**, built lazily on first user gesture (browser autoplay policy), so there is zero audio download weight.
- **Art integration ultimately shipped through the atlas seam.** The first external generation attempt was blocked, but the renderer contract held: authored character strips, boss strips, arena backdrops, UI art and animated VFX now load through stable texture keys while the programmatic atlas remains an emergency fallback.
- **Codex's first core submission was rejected despite a green gate.** It aliased the integers 0 and 1 into `BALANCE.math` (`purchases += BALANCE.math.minTier`) and wrote one statement per file-line. Passing checks is not the bar when `balance.ts` has to stay a readable tuning surface for Phase 6.
- **Atlas frames need a transparent gutter.** The shelf packer originally packed frames edge-to-edge; upscaled 2x with linear filtering, the white FX frames bled a visible white arc into neighbouring character sprites in the arena. `PAD = 4` fixes it. Any real sprite sheet dropped in later needs the same gutter.
- **Arena layout is a set of disjoint vertical bands** documented in `theme.ts`. Enlarging the sprites without re-deriving the bands put each health bar across the fighter it described; the band comment exists so the next size change re-derives rather than nudges.
- **Health bar labels sit inside the bar.** Above-bar labels collided with the enemy name in the arena rhythm, and an inside label makes the bar one self-contained band callers can place anywhere.
- **Headless Chromium measures ~35 FPS on SwiftShader regardless of game cost.** The verification harness forces ANGLE/Metal; the game runs a locked 60 FPS on a real GPU. Never tune performance against a software-rasterized number.
- **Pacing is a test, not a vibe.** `tests/pacing.test.ts` simulates a full ten-minute run against the Phaser-free core and asserts PLAN §Pacing as bounds. The first run exposed a hard failure no browser session would have found: the player peaked at Tier 4 around 30s and then **stalled for 8.7 straight minutes** (64 defeats, 9 coins, zero possible actions).
- **Three balance faults behind that stall:** (1) the anti-stall trickle only fired on an *empty* board, so unmergeable singletons + no coins locked forever; it now fires whenever the player cannot act, scaled to buy cost; (2) rewards compounded per five-enemy block while costs compounded per purchase, so income fell behind spending — rewards now compound per enemy index; (3) losing cost nothing, so an under-powered champion retried the same full-health enemy forever, so each consecutive loss now shaves 16% off the rematch (floor 40%), invisibly.
- **The simulated player is an upper bound, not a real child.** It merges the instant a pair exists with a 700ms action delay, so it hits milestones far faster than a 6-12 year old will. Bounds are asserted on both sides so a future tune can neither stall the run nor collapse the opening into a cutscene.
- **Never schedule an effect's cleanup with `scene.time.delayedCall` when hit-stop exists.** That timer is scaled by the same `time.timeScale` the hit-stop sets, so a 55ms hit-stop restored itself after ~3.8 SECONDS of slow motion, and a 70ms white hit-flash could leave a sprite stuck solid white. Both now restore on `window.setTimeout` wall-clock time. This also fixed board sprites stranded mid-tween.
- **Only one arena banner at a time.** A defeat and a new-tier reveal can fire in the same instant and rendered two messages stacked on top of each other; the banner is now a single container that replaces its predecessor.
- **Bright dojo palette replaces the navy-on-navy scheme.** Sky gradient, packed-earth ground with a straw fight-mat, bamboo and red banners in the arena; warm plank deck with recessed slot markers for the board. Tier 1 is a beige gi and tier 2 a lighter navy so the two lowest tiers are distinguishable without reading their badge. Characters were enlarged inside the 128px frame rather than upscaled at render time, so they fill the slot without blurring.
- **A settings panel is in, against PLAN's "no settings screens".** The owner asked for one directly: a gear beside the almanac book opens music and sound sliders plus Restart Run. Volumes live in their own localStorage slot (`mn.audio`), separate from the run save, so wiping a run never resets the player's audio. The music slider drives a real gain node that nothing feeds yet — PLAN §Audio always wanted a music hook, and this is it, so a track added later arrives already wired and already respecting the saved level.
- **Restart deletes the save rather than calling `resetRun`.** `resetRun` keeps the almanac's discoveries, which is right for the debug panel and wrong for a player who asked to start over. Settings' Restart calls `GameCore.wipeSave()` and then `scene.restart()`, so every widget is rebuilt against a core that found nothing to load. A wiped core refuses to save again — otherwise its next dirty flush writes the dead run straight back before the new scene boots.
- **`GameCore` is built in `GameScene.init`, not as a field.** `scene.restart()` reuses the scene instance, so a field initialiser would have handed the rebuilt UI the old core.
- **Input goes on the Rectangle, never on a wrapping Container.** The settings buttons were first built as `Container(rect + label)` with `setInteractive(hitArea)`; presses fell straight through to the modal shade behind them and closed the panel. The sliders, built as bare interactive Rectangles, worked first time. Same pattern as `BuyButton`.
- **The bitmap font has no lowercase glyphs.** `START OVER FROM AN EMPTY DOJO.` rendered as `S .` in sentence case. Every string handed to `bitmapText` must be uppercase.
- **The design canvas now follows the window's aspect instead of being fixed.** Phaser's FIT mode letterboxes whatever the design does not match, and the two fixed designs (720x1204, 1440x590) left black bands eating a third of the screen on a 1440x900 laptop and a 390x844 phone. `configureLayout` now keeps the tuned *width* and derives the height from the viewport, so the canvas fills the window edge to edge. Panels grow into the extra room up to a cap and the rest becomes centred dojo backdrop — a 3-row grid stretched over 900px of screen would look worse than the black bars did. Every vertical number is now a share of the panel it belongs to, and `tests/layout.test.ts` pins the tuned compositions so the design sizes still reproduce the hand-placed originals exactly.
- **The bottom rail lost its own deck texture.** `dojo_roster_deck` tiled under the coins, Buy button and trash bin read as a separate strip pasted over the dojo floor. With the backdrop now covering the whole canvas there is nothing to replace it with: the rail sits directly on the room the rest of the screen is in. The roster *panel* still uses that texture as its interior.
- **Zero health ends the run.** It used to revive the line at 58% and emit `playerDefeated`, which meant the health bar was decoration -- a run could not be lost. Health now lands on exactly zero, `GameCore` freezes (`update` returns immediately), the save slot is deleted so a reload starts fresh rather than resuming a corpse, and `GameOverPanel` shows the run's numbers behind one TRY AGAIN button. There is deliberately no tap-outside and no close cross: an accidental dismissal onto a frozen board would read as a crash.
- **Boss swings are capped at a share of the line's maximum health (`player.maxHitShare`).** Making death real exposed an arithmetic problem the old revive had been hiding: strike power compounds 5.5% per stage while the line's health only grows with the roster, so the pacing simulation's competent player died at 101 seconds no matter how the raw numbers were tuned. Capping each swing at 1.8% of maximum health (with the victory heal raised 0.18 -> 0.24) puts survival back in the player's hands: a full line takes about two minutes of unanswered swings to fall, so runs end when DPS stops killing bosses fast enough to keep the heals coming. Tuned against `tests/pacing.test.ts`, where competent play now survives twenty minutes and dips to roughly a fifth of its health.
- **Potions are the counterweight to a losable run, and their cadence lives in `src/data/pickups.ts`.** The clock's tuning sits with its widget, but the potion's had to be readable from the unit suite, which cannot import Phaser. Bottles drop about twice as often as the clock, do not spawn at all at full health, and come much faster below 40% -- losing should take a run of bad decisions rather than one unlucky spawn timer.
- **The low-health warning is four stretched gradient strips, not a frame.** A hard-edged red border reads as a broken layout; soft bands built from two one-pixel canvas gradients read as danger. It is non-interactive at depth 320 so it can never eat a tap aimed at a merge, and it stands down the moment the game over screen appears.
- **Powerups and the New Ninja ceremony use dedicated textures.** Reusing generic star, puff, coin, ring, panel, platform and button frames made different rewards read as the same object and left the reveal looking assembled from spare UI. Each powerup now loads one compact standalone icon, while the reveal owns a coordinated dojo backdrop, rank halo, plinth, banner and action plate.
- **Wallet gains never resize the coin icon.** The old “amplitude” constants were already scale factors (1.22–1.45), then were added to one again; that drove vertical scale to almost zero or negative during a payout. Income now hops and tilts the fixed-size icon, with glow, spark and text feedback carrying the reward magnitude.
- **New Ninja placement follows visible pixels, not sprite cells.** The 29 character strips carry very different transparent padding (the final dragon occupies only the bottom 106px of a 256px frame), so centering the raw frame displaced the actual silhouette. The reveal owns per-tier opaque bounds, anchors the visible centre and feet to the plinth, cover-crops its backdrop without distortion, and reserves non-overlapping vertical zones for banner, hero, stats, and action button.
- **The music hook now feeds a synthesized chiptune loop (`src/audio/Music.ts`).** The theme is an original composition played live by WebAudio -- A-hirajoshi pentatonic lead over an Am-F-C-G engine at 132 BPM, sixteen bars with a stated-twice taiko-gallop hook, a climax octave leap, and a held dominant turnaround so the loop pulls the ear back to its top. Synthesizing it keeps the zero-download decision intact (PLAN §Audio); the first user gesture that unlocks the AudioContext also starts the loop through `Sfx.playMusic()`, which is idempotent. The scheduler uses a 1.35 s lookahead so background-tab timer throttling cannot punch gaps in playback, and everything runs through the pre-wired music bus, so the settings slider and saved level apply untouched.
- **The damage ladder moved into config and grew teeth (`balance.progression`).** `dps(tier) = round(dpsBase * dpsGrowth^(tier-1))` with base 3 and growth 2.4 replaces the hardcoded `1.85^index` in `ninjas.ts`. The old growth meant a merge -- two tier-N ninjas for one tier-(N+1) -- left the board with 7.5% LESS total DPS than before it; the core verb of a merge game was a DPS tax. Growth 2.4 makes the same trade worth +20% (target `mergeSpikeTarget`, asserted per-pair in `tests/combat.test.ts` within ±0.05), inside the 15-45% spike window we wanted, and it is the steepest growth whose tier-29 value (~5.5e10) still formats as "55B" through compactNumber's K/M/B suffixes -- anything past 2.9 spills into bare 13-digit integers. Base 3 instead of 1 is not cosmetic: at base 1 the first merge rounds to either "no gain" or "+50%" and no tolerance band survives integer quantization that small.
- **Costs were retuned around one contract: blended price growth must sit just under DPS growth.** Shop cost compounds twice, per purchase (`costGrowth` 1.03) and per shop tier (`tierCostMultiplier` 2.1). Income compounds 2.4x per champion tier. With the blend above ~3.2 purchases collapsed from 30+/minute to 1/minute by minute ten and the pacing sim died hungry at eleven minutes; with it at ~2.07 the run sprinted to tier 29 by minute seven with nothing left to chase. ~2.5 throttles buying to a self-limiting trickle that still feeds the ladder. Sell refunds now pay exactly half the tier's base shop price (they drifted a coin off under single rounding).
- **Late-game survival is arithmetic, and the arithmetic was losing.** Boss HP compounds 1.30 per stage forever while board DPS only jumps when the champion climbs, so late TTK stretches out, victory heals space apart, and the capped chip damage wins the long game -- the sim died at nineteen minutes on a cap of 1.8% per swing. The swing cap is now 1.3% of maximum health and victory heals are 30% (was 24%): a run mid-slide, killing a boss every half minute, still out-heals the chip between kills. The raw strike curve (`attackDamage*1.055^stage`) only shapes the first handful of stages; past them every hit rides the cap, which is the point -- incoming damage should be a constant the player can read, not a second exponential racing theirs.
- **Tempo phases now carry the economy relief valve.** From SURGE (10 min) on, `buyTierOffset` holds at 3 instead of stepping down to 1-2: purchase-count inflation has compounded for ten minutes by then, and a shop priced near the champion produced 20+ second unaffordable stretches. Cheaper shop tiers keep buys flowing AND deepen the merge ladder feeding each new champion tier, which is what keeps the last stretch earned. ONSLAUGHT pays x1.55 and ASCENSION x2.0 (were 1.1/1.4) for the same reason -- those phases are where the cost curve bites, and a reward dip there starves buys, thins the line, slows kills, and cuts the heals: a four-step death loop the sim found twice.
- **Merges used to cost power; now they pay.** The tier ladder grew at 1.85x per tier, so combining two ninjas kept 92.5% of their combined DPS -- merging made you weaker. Growth is config now (`balance.ts` progression block) at 2.4x, which pays a 17-22% spike per merge across all 28 pairs, pinned by a full sweep in `tests/combat.test.ts`. The whole numeric loop (boss curves, costs, tempo) was retuned against an expanded `tests/pacing.test.ts` that plays like a child -- jittered reaction times, distraction pauses, occasional bad calls -- and asserts action gaps (<=12s early), affordability waits, actions/minute, milestone timelines, health trajectory and a hard stall bound over both the ten-minute and twenty-minute horizons.
- **The golden clock no longer skips ahead in the story.** A 10-second x10 boost used to advance the session/tempo clock by ~100 simulated seconds, shoving a player through phase changes they never played. Combat and income still run at full boost; only the tempo clock is capped (`phaseClockAdvance`, max 2x real time), verified by both the unit suite and verify-clock.mjs watching the two clocks diverge live.
- **Reloads can no longer invent a ninja.** The dev preview seed was a decision table buried in GameScene; it is now a pure helper (`src/data/devPreview.ts`) whose rule is simple: only explicit URL params seed, everything else -- HMR, full reloads, relayouts, production, fresh boots -- touches nothing. There is deliberately no implicit tier-1 starter anymore: a new run starts through the real economy, and "board starts empty" is a passing browser check.
- **Powerups are a framework, not two more one-offs.** `src/systems/PowerupSystem.ts` (pure, seeded, injectable) plus `src/data/powerups.ts` drive five pickups: Shuriken Frenzy (DPS x2 / 12s), Smoke Bomb (boss attacks freeze 7s -- the attack meter CLAMPS rather than queueing a burst for when the smoke clears), Lucky Charm (coins x2 / 18s, extend-stacking), Protective Ward (banks 3 charges that eat strikes before the damage clamp), and Coin Frenzy (rare manual coin rain). They are session luck by design: never saved, cleared on game over and ascension, spawn-gated on the run being alive and unpaused, durations frozen while a modal is open.
- **Boss entrances are data, not one portal fits all.** `src/data/bossVfx.ts` resolves all 37 identities to hand-tuned recipes (portal/pillar/riftTear/summonCircle/skyFall/eruption families); late dragons get shake-2 sky-falls and eruptions. ArenaManager choreographs them through an injected presenter; CombatDirector got out of the way. Static creatures and dragons also got motion recipes (`presentation.ts`) -- breathe/serpent/winged/brute/spirit transform layers suited to each silhouette instead of a humanoid sword lunge, always additive under authored frames and never gating gameplay.
- **The arena moves through five acts, but stage 1 owns the visual bar.** Dojo dusk, mountain temple, storm sea, rift and dragon shrine are selected deterministically by stage (`arenaThemes.ts`) with a short crossfade at act lines, tinted portals/VFX, and per-theme procedural floor strips replacing the squashed bg_floor rectangle. Every later backdrop is authored from `dojo-night-backdrop.png` as the explicit reference for pixel density, cinematic Japanese architecture, detail and lighting. Floors stay separate and restrained; Storm and Rift deliberately share the Dragon Shrine's stable slab geometry in navy and purple because their former wet-rock streaks and shard teeth read as broken foreground layers.
- **Money you can watch.** Boss defeat now pays in stages: a bounded volley (<=16 sprites regardless of reward size) bursts, falls onto the platform with damped bounces, settles, then magnetizes to the wallet one coin at a time -- small blip per arrival, bigger squash-and-glow finale on the last. The wallet icon got larger with jelly feedback, and rapid income coalesces so the counter never strobes. Core still awards exactly once; presentation cannot mint coins.
- **Purchases land in smoke, swaps read as swaps.** Buying hides the recruit in a charcoal smoke bloom (<=450ms, interruptible, never fired for loaded saves or relayouts since those emit no spawn event). Drag targets now speak five states -- gold magnet pulse for merges, cool lean for swaps, faint outline for empty cells, red breathing ring for trash, shake-back for invalid -- and dropping a max-tier pair onto itself trades places instead of silently refusing (core falls through merge->swap).
- **The NEW NINJA card is dojo-built now**: atlas nine-slice panels over a dark plate, the actual animated hero on a plinth, tier badge, name and a DPS-delta line, escalating spectacle for milestones, wall-clock beat tokens so hit-stop cannot strand it, same queue/pause/first-release-swallow contract as before. And the theme track survives tab suspension: the scheduler fast-forwards its pattern after long stalls instead of dumping a burst of notes, every persistent node disconnects on stop, and visibilitychange resumes a suspended context.
- **Creature bosses animate from authored eight-frame strips.** The 15 identities previously tagged `animalStatic` now own anatomy-specific 2048×256 RGBA sheets: eight equal 256px cells covering anticipation, strike, impact, recoil, and recovery. Idle only alternates the first two restrained poses; attack playback runs all eight and reports damage on frame five. This avoids making birds, spiders, bears, serpents, and hydras share a humanoid transform lunge.
- **Coin Frenzy is rare, manual money—not passive income.** Its five-minute eligibility window only offers the pickup on an 18% seeded roll, with six-to-ten-minute retries, so it is a surprise rather than a guaranteed beat. Catching it rains 36 large tap targets across the whole responsive canvas; only clicked coins pay, missed coins expire, and each coin freezes to one-sixth of the current stage's canonical boss reward so the event scales without adding another economy curve. A perfect clear is about six boss bonuses, while an ordinary imperfect clear pays less.
- **Gameplay VFX are authored animation strips, not atlas polygons.** Slash, smoke, shockwave, portal, flame, lightning and merge magic each ship as an eight-frame 2048×256 transparent strip registered in `vfxAssets.ts`. Combat, boss entrances, purchases, power-up auras, coin arrivals and reward/reveal bursts reuse pooled sprites and tint those neutral frames to preserve the existing gameplay palette; the small legacy atlas primitives remain only as compact icon/fallback material.
